# SHA-256 text-patch experiment

Scope: a pure, path-free compiler inspired by Forge's hash-bound line patches.
It consumes original bytes and ordered replacement hunks, and returns complete
result bytes with source/result byte ranges. It performs no filesystem, provider,
database, or runtime operations. Existing PatchArtifact, prompts, MCP and CLI
contracts are unchanged. No automatic fallback or production wiring is included.
The exported Rust types are an experimental library API for offline callers;
they are not new MCP/CLI or model-response schemas.

## Contract

- Whole-source and hunk hashes use existing `sha256:<64 lowercase hex>` encoding.
  Callers supply hashes from the exact source snapshot; models need not compute them.
- Ranges are one-based, inclusive, sorted, non-overlapping, and refer to the
  original source, even when an earlier replacement changes its line count.
- LF, CRLF and lone CR each terminate a line. Terminators belong to their line;
  a final terminator creates no phantom line. UTF-8 BOM bytes are ordinary content.
- Replacement text is verbatim. Removing a terminator can intentionally join
  lines; adding one can split a line. Unselected bytes are preserved exactly.
- Source, aggregate replacement and result each have a 1 MiB ceiling; at most
  128 hunks. Check sizes before allocating result storage.
  These are compiler bounds, not JSON decoding bounds: a future transport must
  limit incoming bytes before Serde allocates strings or arrays.
- Empty source, malformed hashes, stale whole/range hashes, NUL/non-UTF-8 source,
  NUL replacement, invalid ranges and exceeded bounds return typed errors.
- Empty replacement removes selected text, not a filesystem entry. Unchanged
  output is valid computation, not evidence that a task implemented anything.
- No zero-width insertion, file creation/deletion, or binary patch contract.
  Unsupported input returns an error, never a different operation.
- Validation precedence: source size/text, whole hash grammar/match, all hunk
  metadata (count, ranges/order, replacement text/budget, hash grammar), original
  source spans and range hashes, then final output size. Errors report zero-based
  hunk indices; source coordinates remain one-based.

## Verification plan

Focused tests use expected byte results and geometry, a known SHA-256 fixture,
mixed delimiters/Unicode/BOM, adjacent multi-hunk edits, boundary errors, resource
bounds and closed serde input. A generated finite corpus checks byte preservation
against an independent fixed-span splice. Run focused tests, then canonical
`make ci` (rules, format, workspace check, strict Clippy and tests).

This experiment does not establish model output savings or production readiness.

## Executed result — 2026-11-04

The initial behavior run failed 7 of 8 tests against the unimplemented compiler.
After implementation and the additional multi-line case, focused tests passed
9/9, including 81 generated byte-preservation cases. Independent read-only
review found no compiler correctness defects; its future decoder-budget concern
is recorded above.
